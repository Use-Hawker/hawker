The agent kit

Give an agent a wallet, not a card.

The kit keeps the agent's key on your machine and signs each payment itself. The model only ever sees stalls, prices and answers.

The kit on GitHub

1. Make its wallet

One command makes a key in ~/.hawker/key and prints the address. Send it a few USDG on Robinhood Chain. It never needs ETH.

hawker init
hawker balance

2. Set its limits

Per call and per day, in USDG. Above them nothing is signed, whatever the model asks for.

HAWKER_MAX_PER_CALL=0.10
HAWKER_MAX_PER_DAY=2
HAWKER_TILL=

3. Plug it in

As an MCP server in Claude or Cursor, or straight from a script.

hawker stalls
hawker call rh-wallet \
  '{"address":"0x…"}'

Install

Node 20 or newer. The kit is a few small files with viem as its only dependency, from .

git clone https:// hawker
cd hawker && npm install --omit=dev
cd agent && npm link        # puts `hawker` on your PATH
hawker init

As an MCP server

The server runs on your machine over stdio and holds the key. It gives the model three tools.

{
  "mcpServers": {
    "hawker": {
      "command": "hawker",
      "args": ["mcp"],
      "env": { "HAWKER_MAX_PER_CALL": "0.10", "HAWKER_MAX_PER_DAY": "2" }
    }
  }
}
// .cursor/mcp.json
{
  "mcpServers": {
    "hawker": { "command": "hawker", "args": ["mcp"], "env": { "HAWKER_MAX_PER_DAY": "2" } }
  }
}
ToolWhat it does
hawker_stallsThe catalog: every stall with its price per call and the input it takes.
hawker_callCalls one stall and pays for it from the agent's wallet. Returns the answer and a receipt with the transaction. max_usd refuses the call if it costs more.
hawker_balanceUSDG in the wallet, spent today, and the limits. Never the key.

From code

import { loadConfig, call, verify } from './hawker/agent/hawker-agent.mjs';

const cfg = loadConfig();            // reads ~/.hawker/key and HAWKER_* limits
const { result, receipt } = await call(cfg, 'coin-price', { ids: 'ethereum' });
console.log(result.prices.ethereum.usd, receipt.tx);

// optional: check the receipt against the chain yourself
await verify(cfg, receipt, '');
import { privateKeyToAccount } from 'viem/accounts';
import { keccak256, encodeAbiParameters } from 'viem';

const USDG = '0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168';
const account = privateKeyToAccount(process.env.KEY);
const url = '/v1/call/rh-wallet', body = JSON.stringify({ address: account.address });

// 1. ask: the 402 says who to pay, how much, and the call ref
const q = (await (await fetch(url, { method: 'POST', body })).json()).accepts[0];

// 2. sign a USDG authorization to the till; the seller and ref ride in the nonce
const p = { from: account.address, seller: q.seller, value: q.value, validAfter: '0',
            validBefore: String(Math.floor(Date.now() / 1000) + 300), ref: q.ref };
p.signature = await account.signTypedData({
  domain: { name: 'Global Dollar', version: '1', chainId: 4663, verifyingContract: USDG },
  types: { ReceiveWithAuthorization: [
    { name: 'from', type: 'address' }, { name: 'to', type: 'address' }, { name: 'value', type: 'uint256' },
    { name: 'validAfter', type: 'uint256' }, { name: 'validBefore', type: 'uint256' }, { name: 'nonce', type: 'bytes32' }] },
  primaryType: 'ReceiveWithAuthorization',
  message: { from: p.from, to: q.till, value: BigInt(p.value), validAfter: 0n, validBefore: BigInt(p.validBefore),
             nonce: keccak256(encodeAbiParameters([{ type: 'address' }, { type: 'bytes32' }], [q.seller, q.ref])) },
});

// 3. the same request again, with the payment
const r = await fetch(url, { method: 'POST', body, headers: { 'x-payment': btoa(JSON.stringify(p)) } });
console.log(await r.json());   // { result, receipt: { tx, paidUsd, sellerGotUsd, feeUsd } }

Settings

VariableDefaultMeaning
HAWKER_KEY~/.hawker/keyThe agent's private key, or a file that holds it.
HAWKER_MAX_PER_CALL1The most one call may cost, in USDG.
HAWKER_MAX_PER_DAY5The most the agent may spend in a UTC day. Kept on disk in ~/.hawker/spend.json.
HAWKER_TILLnonePin the agent to one till: a quote naming any other contract is refused.
HAWKER_APIhttps://usehawker.funThe gateway.
RH_RPC_URLpublic RPCRobinhood Chain RPC, used for balance and verify.

Questions

What stops a prompt injection from draining the wallet?

Three things, none of them the model. The wallet only holds what you sent it. The kit refuses to sign above the per-call and per-day limits. And each signature pays one named seller one exact price for one call: it cannot be reused or pointed elsewhere.

Does the agent need ETH for gas?

No. The agent only signs. HAWKER's settler sends the transaction and pays the gas.

What if the stall fails after I signed?

The payment only lands after the stall answers. If it fails, the signature is never used and nothing moves. It stays valid for its five-minute window, so a retry does not need a new one.

Can HAWKER take more than the price?

No. The signature is for an exact amount, made out to the till contract, and the till sends it to the seller named in the nonce minus the fee. The fee is capped at 5% in the contract.

How do I take money back out?

It is the agent's own wallet: send the USDG anywhere with its key, like any other wallet. There is nothing to withdraw from HAWKER.
